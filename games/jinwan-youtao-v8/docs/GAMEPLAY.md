# 经营版交接

保持已认可的 Hyatt Place 主屏，继续在同一预览路径交付。旧正式页面不变。

## 可操作循环

- 来客按星期、定位、价格、天气生成；商务、度假、长住与会员等级影响需求，多晚住宿跨日保留。
- 前台选择房间办理入住；Globalist 享套房升级价；可预留/释放房间、婉拒来客。
- 住客在房间、早餐、酒廊、健身房、屋顶活动；消费、库存、容量与满意度相连，气泡来自住客状态。
- 到期退房留下脏房，清洁/维修带定时任务；装修改变软装并提高新客价格。
- 现金、每日成本、房费、ADR/RevPAR、入住率、升套、客诉与日结收入趋势。
- 前厅/客房/工程/餐饮/收益主管具有具体自动行为及每日工资。
- 有空间目标、冷却、期限、处理选择和正反馈的事件；持久日志按类别过滤（含「抉择」）。
- 每日任务、奖励领取；4× 从第一天可用；面板打开及页面隐藏时经营暂停。
- 客房可扩建到 8F；设施层与屋顶实际上移，scene graph、房号与 rail 同步。
- v8 独立命名空间自动保存，每五秒及页面隐藏时保存；可导出 JSON；新开带确认和 reset guard。

## 总经理的一天

晨会（预测、经营方向、昨日决定的回响）→ 经营决策（房价、留套、备货、人手、预算）→ 现场运营 → 突发事件与经营抉择 → 20:00 复盘（今天的决定与结果）→ 午夜结算 → 次日后果。

- **经营抉择**（`core/dilemmas.ts`）：会展团队超售、会员免费升套、客房部加班或抽调、噪音投诉补偿、每周预算（营销 / 培训 / 维护 / 留现金）。每个选项实时显示对现金、体验、业主、团队精力和后续收入的影响，并附部门建议；超时按保守方案自动处理并写入复盘。
- **延迟后果**：差旅负责人升套后次日带来协议订单，博主 / 论坛会员影响次日口碑；在晨会以「昨日决定的回响」出现，并回写到决策记录。
- **调度**：同一时间只有一个抉择；同类不连续两天出现；每天最多 2 个（Day 7 起 3 个），间隔不少于 150 分钟。
- **晚退与生日**：Globalist 4PM / Explorist 2PM 晚退卡显示下午到店人数与可用房，房间不够时才记为抉择；生日礼遇在早餐、升套、手写卡、维持原预订之间取舍。
- **团队精力**：满房、加班、抽调消耗，空闲与培训恢复；低于 60 翻房变慢，低于 35 明显拖慢，计入评分与晚间复盘。
- **满房保护**：可售房用尽时散客被告知客满而不排队；散客会挤占确认预订时，前台提示并由前厅主管自动婉拒。

所有抉择、诉求和事件使用同一张卡（`screenKit.decisionCard`）：当前情况 → 建议 → 选项与影响 → 操作 → 底部明细链接。

## Day 1–3 带教

单线 checklist，按天分组，完成当前一步才解锁下一步，次日课程显示「明天解锁」，期间自由经营。

- Day 1 接住第一批客人：晨会 → 亲自入住（带教期间排队客人不流失）→ 翻房 → 20:00 复盘。
- Day 2 餐饮与会员承诺：按早餐预估备货 → 处理必定出现的会员晚退（自动打开决策卡）→ 聘任客房主管。
- Day 3 经营方向与两难抉择：晨会选方向（解锁房价与留套）→ 第一个经营抉择（必定生成并自动打开）→ 20:00 复盘后独立接班。

旧存档的五步带教进度按对应课程迁移。

## 规则

1 秒真实时间 = 4 游戏分钟，4× = 16 游戏分钟。逐分钟处理业务，不跳事件。午夜按在住客人锁定房费结算一次，日结暂停，确认后开启次日。无后台离线收益。房间面板打开时亦暂停，方便在手机上操作。

核心逻辑在 `src/core/game.ts`，存档在 `core/save.ts`；store 始终是唯一数据来源。renderer 仅按布局/房态变更更新建筑，按住客状态更新人物。经营日志不按 toast 生命周期删除。

## 本轮检查

TypeScript + production build；`npm test` 覆盖七天自动运营、带教 Day 1–3、各类抉择的结果与延迟后果、超时与撤销、调度上限和抉择卡信息顺序。`tests/sim-playthrough.mts` 是脚本化玩家（`FREE=1` 跳过带教），用于观察一周的现金、口碑、团队精力和抉择分布。手机视口浏览器走查：晨会 → 接待 → 入住、checklist、房态与 3D 点房、Day 2 晚退自动弹卡、聘任、Day 3 方向与抉择、决策记录、20:00 复盘与接班。

## 保留边界

当前品牌为 Hyatt Place。其他五品牌与独立 SPA 美术尚未开放，避免只换品牌名。旧 v5/v7 存档不会自动导入；用户原进度保留在原 namespace。JSON 导出目前用作备份，未开放导入界面。后续可基于用户试玩反馈补足，而不静默套用不兼容的旧房间结构。
