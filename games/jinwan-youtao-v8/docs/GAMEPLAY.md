# 经营版交接

保持已认可的 Hyatt Place 主屏，继续在同一预览路径交付。旧正式页面不变。

## 可操作循环

- 来客按星期、定位、价格、天气生成；商务、度假、长住与会员等级影响需求，多晚住宿跨日保留。
- 前台选择房间办理入住；Globalist 享套房升级价；可预留/释放房间、婉拒来客。
- 住客在房间、早餐、酒廊、健身房、屋顶活动；消费、库存、容量与满意度相连，气泡来自住客状态。
- 到期退房留下脏房，清洁/维修带定时任务；装修改变软装并提高新客价格。
- 现金、每日成本、房费、ADR/RevPAR、入住率、升套、客诉与日结收入趋势。
- 前厅/客房/工程/餐饮/收益主管具有具体自动行为及每日工资。
- 有空间目标、冷却、期限、处理选择和正反馈的事件；持久日志按六类过滤。
- 每日任务、奖励领取；4× 从第一天可用；面板打开及页面隐藏时经营暂停。
- 客房可扩建到 8F；设施层与屋顶实际上移，scene graph、房号与 rail 同步。
- v8 独立命名空间自动保存，每五秒及页面隐藏时保存；可导出 JSON；新开带确认和 reset guard。

## 规则

1 秒真实时间 = 4 游戏分钟，4× = 16 游戏分钟。逐分钟处理业务，不跳事件。午夜按在住客人锁定房费结算一次，日结暂停，确认后开启次日。无后台离线收益。房间面板打开时亦暂停，方便在手机上操作。

核心逻辑在 `src/core/game.ts`，存档在 `core/save.ts`；store 始终是唯一数据来源。renderer 仅按布局/房态变更更新建筑，按住客状态更新人物。经营日志不按 toast 生命周期删除。

## 本轮检查

TypeScript + production build；一项覆盖七天自动运营、跨日房费唯一入账、入住与 8F 扩建的快速测试。用户已要求自行进行画面与体验检查，本轮不做重复浏览器 / 真机测试。

## 保留边界

当前品牌为 Hyatt Place。其他五品牌与独立 SPA 美术尚未开放，避免只换品牌名。旧 v5/v7 存档不会自动导入；用户原进度保留在原 namespace。JSON 导出目前用作备份，未开放导入界面。后续可基于用户试玩反馈补足，而不静默套用不兼容的旧房间结构。
