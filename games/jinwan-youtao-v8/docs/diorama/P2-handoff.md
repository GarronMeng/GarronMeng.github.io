# P2 · 客房类型与装修等级

P1 照片导向的嘉轩客房方向获确认后，本轮只推进 P2：客房类型、床型、等级与对应交互。大堂、公共设施、酒店外立面、人物行为和 UI 均未重做；原经营预览未覆盖。

## 真实状态 → 视觉配置

读取原有 `Room.category / type / bed / level / status / construction / extraBed / suaBookingId`，不创建展示存档、不改变经济参数。

| 游戏房型 | 可见区别 |
| --- | --- |
| 普通客房 | 保留已确认的照片导向布局、普通窗幅、窗边躺椅 |
| 景观客房 | 更宽的真实几何窗洞、窗框、窗台和帘盒 |
| 套房 | 宽窗、带靠背与扶手的沙发、茶几和木格栅分区 |
| 尊享套房 | 套房布局加石材台面与窗台、独立阅读灯 |

四房型均支持大床 / 双床：双床为两张独立床架、床垫、被面和床头软包，非在大床上画分隔线。游戏中的“景观 / 套房 / 尊享套房”是现有玩法分类，新增装修设计沿用已确认的实景视觉语言，**不声称这些等级与布局是凯悦官方装修标准或逐间测绘复刻**。P1 的照片来源继续见 `HYATT-PLACE-REFERENCES.md`。

| 装修等级 | 相比前级的几何变化 |
| --- | --- |
| Lv1 | 深木床头、白床品、媒体工作台、白色办公椅、窗边休息位 |
| Lv2 | 定制床尾织物、装饰靠枕、床头缝线层次 |
| Lv3 | 阅读落地灯、叠搭软包、地毯包边 |
| Lv4 | 石材洗漱柜、台盆、水龙头、背光镜面 |
| Lv5 | 顶部灯槽、成对装饰画、格栅柜面与床架细节 |

等级叠加于房型，不替代房型；40 种组合均可构建。高级柜体/洗漱区为视觉资产，不新增经营功能或伪造住客使用行为。所有布局保留原房间尺度与前方走廊。

## 施工、房态和点击

- 未配置的空房继续显示原有“＋”；房间或楼层施工期间继续显示原施工呈现。
- 真实施工结束、原 `level` 增加后才显示对应装修，未提前显示竣工。
- 行李、清洁车、工程标记、SUA 与加床保留真实状态绑定。
- 所有客房均可进入局部剖面视图，不再只支持 201。相机、点击体和气泡使用当前真实房间 ID。
- 局部视图只显示该房间的建筑剖面与实际进入空间的人物；完整酒店保留全部住客和员工。
- 同款房间共享几何，但墙体隐藏、实体 ID 和房态物件各自独立，避免点 A 房选中 B 房或一起隐藏墙体。

## 资源策略

`variants.ts` 定义房型/等级特征；`templates.ts` 按真实外观键缓存并合并静态材质批次。只有脏床品影响主体模板键，入住/清洁/维修/预留标记是独立房态物件，不为每次房态改变复制整间几何。每次场景重建后移除不再使用的模板，释放其合并几何；销毁世界时释放全部模板。

基础普通大床房主体约 24 个模型提交对象，前版约 70；这不是 GPU 实测 draw calls，阴影通道与视锥裁剪会改变实际计数。同款房间复用合并几何和材质，避免全酒店逐件重复提交。诊断数据增加当前模板数量和合并几何字节估算。

新开游戏 9 间客房的 Node 结构统计：229 个模型提交对象、290,830 个三角形，主体仅需 3 个当前模板，几何属性约 8.82 MB。以上不含公区、城市和人物，也不是显存或 FPS 实测。
